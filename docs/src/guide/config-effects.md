# Configuration Effects (Visual)

> This page documents the **visual effect of each configuration switch**:
> an off/on screenshot pair plus a transition GIF, regenerated by
> `scripts/docs_gif.sh`. It complements [Client Settings](/guide/settings) with
> the before/after evidence and doubles as a configuration-effect regression
> gate (the pipeline fails if an off/on pair shows no pixel difference).

Every entry below is a switch whose flip has a visible effect. The **off** image
is the state before the switch, the **on** image after, and the GIF is the
transition (a crossfade between the two).

## Theme (light / dark)

**Where**: Settings → General → 主题 (theme dropdown). Switching from light to
dark restyles the whole client (chat window, lists, dialogs, and the settings
panel itself). Off = light, on = dark.

## External uplink port (server CLI)

**Where**: `memex_server serve --uplink-port <port>` (R23-4). Off = no external
ingress face (the server only listens on the intranet); on = a separate

## Pipeline

`scripts/docs_gif.sh` is re-runnable and regenerates everything:

1. Rebuilds `test_settings_window` and `test_mode_switch`.
2. Re-runs them (the settings-window test block ⑨ emits the `config-effect-*`
   off/on PNGs; the mode-switch test emits the `layout-chat-*` theme pair).
3. Asserts each off/on pair **differs in pixels** (`compare -metric AE > 0`) —
   a switch with no visible effect fails the pipeline (regression gate).
4. Fuses each pair into a GIF with `ffmpeg xfade` (crossfade, palette-optimized).
5. For the CLI switch, captures the real `serve --uplink-port` output and renders
   it into terminal-style frames (asciinema is not available in this
   environment; the frames are rendered from the real command output instead).

Artifacts land in `docs/src/public/screenshots/` and
`docs/src/public/screenshots/gifs/`.
