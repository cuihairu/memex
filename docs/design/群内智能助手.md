# 群内智能助手设计稿（平台三期·line164）

四件套：**群内智能助手 · 会议纪要生成 · 需求整理 · 智能检索（检索增强）**
——一个内置编排器（GroupAssistantWorker）：以 bot 身份轮询所在群的群
消息与私聊，识别指令，走模型网关（line163）生成回答，以 bot 身份回群。
检索增强的资料来自**留痕归档**（bot 所在群的消息天然在检索半径内）。

## 0. 范围

**本笔落地**：四指令（@助手／@纪要／@整理／@检索）、RAG 上下文注入、
回群投递、serve 装配（--assistant）、全链测试。

**留后续（如实注明）**：@提醒/@待办 等指令扩展；按群配置指令开关；
多轮对话（上下文记忆）；流式回包（网关 SSE 后跟进）。

## 1. 形态与线程

- 编排器=serve 内独立线程（`--assistant <bot名>` 显式开启），轮询
  `pending_offline("bot:<名>")`（TEXT 扇出自动入队——与外部 bot 同一
  收信面）；
- **回群走回环 HTTP** `POST /bot/send`（复用既有鉴权/校验/投递链；
  deliver_notice 需 CollabServer 在线表——无锁，跨线程不可用，故不
  直调）；bot token 经 `--assistant-token`（值进 ps，建议 env
  `MEMEX_ASSISTANT_TOKEN`，同 --tool-cred-secret 口径）；
- 模型调用走同进程模型网关回环 `http://127.0.0.1:<model-port>`，
  Bearer=同 bot token。

## 2. 指令（前缀写死，中文产品口径）

| 指令 | 行为 | 模型 |
| --- | --- | --- |
| `@助手 <问题>` | RAG：所在群最近 20 条归档消息作上下文＋问题 | 走网关 |
| `@纪要` | 所在群最近 50 条 → 纪要模板（要点/结论/待办） | 走网关 |
| `@整理 <文本>` | 结构化需求模板（背景/目标/功能点/验收标准） | 走网关 |
| `@检索 <关键词>` | 归档命中列表格式化回群 | **不走** |

- 群上下文检索：`search_messages(account="bot:<名>")`——账号过滤天然
  含「所在群全部群消息」（group_members 子查询）＋涉 bot 单聊；按
  `to_account==目标群` 再筛；上限内取最近；
- **网关请求一律带 `memex_archive_scope:true`**——上下文/资料来自归档
  数据，红线（仅本地模型）原样生效：无本地端点即回群明示「归档数据仅
  本地模型，当前无可用本地端点」；
- 回复目标：群消息触发→回该群；私聊 bot 触发→回发起人；
- 非指令消息不处理（ack 清队跳过）；处理完即 `ack_offline`。

## 3. 失败口径

| 情形 | 行为 |
| --- | --- |
| 网关不可达／503（含红线拦截） | 回群错误提示（含原因），不重试 |
| 上游 4xx | 回群「模型拒绝」＋原因 |
| 回环 /bot/send 失败（webhook 口关闭） | 日志留痕，消息已 ack 不重投 |
| 指令格式缺参 | 回群用法提示 |

## 4. serve 装配

```
memex_server serve --assistant <bot名> [--assistant-token <明文>]
    --webhook-port N --model-port M
```

- assistant 开而 webhook 口关→启动失败明示（回群面不存在）；
- model-port=0 时 @助手/@纪要/@整理 回「模型未启用」；@检索 不受影响。

Server＋假上游（同 test_model_gateway）＋真 Worker（轮询间隔 100ms）。
