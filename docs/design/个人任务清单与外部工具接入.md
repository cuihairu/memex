## 0. UI 定位(2026-10-04 用户拍板)

任务清单入口=**左侧菜单栏一级菜单**(与会话/通讯录同级,常驻可见),不埋在个人设置页内——高频独立面,桌面端左栏、移动端一级 Tab。

## 1. 个人 todolist 设计要点

- **每个人有自己的任务清单**：自己添加、勾完成、设提醒；
- **他人分配**：别人（同群/同组织，按权限模型）可以把任务分配给你——出现在你的清单，标来源+可跳转看分配上下文；
- **外部任务**：外部工具（GitHub/Jira/飞书…）的任务经 provider 拉进来展示，**点击跳转外部看详情**（detailUrl），完成状态可回写（按 provider 能力）。

## 2. Provider 分级（接入深度）

| 级 | 能力 | 实现 |
|---|---|---|
| **L1 跳转** | 带 detailUrl 打开外部详情 | URL 模板即可，成本最低 |
| **L2 只读** | 拉外部任务列表/状态展示 | provider 实现 list() |
| **L3 双向** | memex 内创建/完成回写外部 | create()/complete() + webhook 或轮询同步 |

Provider SPI：`id / name / auth / capabilities(L1|L2|L3) / list / create / complete / detailUrl`——能力声明制，工具只实现自己支持的级别。

## 4. 结论与排期建议

- **首批**：本地 todolist（L3 全功能）+ GitHub + 飞书 + 钉钉（provider 各实现到 L2-L3，L1 跳转必带）；
- **二批**：Jira/Linear；其余按用户需求点名再加；
- **不接**：Teambition（停摆）；禅道先 L1 跳转；
- 所有 provider 凭据走加密面（R24 persona 参考件），**跳转链接是基本件**（任何 provider 都必须能跳外部详情）。

### 6.5 看板（R27-6 之三）

- 看板＝**同一批任务数据的另一个视图**，不新建数据模型、不新建通道；
  与现有列表视图并存（可切换）。
- **定案（回执#3）**：个人任务**需要**「进行中」状态——`tasks` 加
  `status TEXT NOT NULL DEFAULT '待办'`（枚举：待办/进行中/完成，默认
  待办）；存量行迁移＝done=1→「完成」，否则→「待办」；group_tasks 与
  外部任务**沿用各自现成状态**（group_tasks 的 todo/done、approvals 四
  态、外部任务带 provider 原始状态），**看板列统一读 status 语义**；
  done 列保留写双份过渡（过渡期读取以 status 为准，迁移收口后 done 只
  作兼容读）。
- 卡片时间：开始时间（start_ms）与截止（due_ms 露出的 deadline）都上
  卡片；**定案（回执#4）**：**逾期标红、3 天内到期标黄**，阈值可配置
  （缺省 3 天）。
- 三端同源：桌面/手机/admin 同一批数据，不出现第二套任务状态。
- **定案（回执#5）**：手机端＝**横滑看板＋窄屏自动降级列表**（两者并存，
  不二选一）；若用户本意只要列表会再纠正，先按此实现。
- 与信箱（docs/design/信箱.md）、OIDC（docs/design/OIDC身份认证接入
  设计.md）两案不冲突：任务到期提醒仍走通知中心，信箱只加「进箱/未读/
  已读」状态视图（其边界①），不搬任务数据。
