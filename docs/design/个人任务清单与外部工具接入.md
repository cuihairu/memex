# 个人任务清单与外部工具接入：调查分析（R27 设计稿）

> 状态：调查分析稿（2026-10-04 用户令「先调查分析，哪些可以接，哪些可以实现」）。范围：个人 todolist（自建+他人分配）+ 外部项目/任务管理工具 provider 接入 + 跳转看详情。互引：todo R27、权限模型（分配=群/组织权限语义）、群工具框架（R25 provider 形态可参照）。

## 0. UI 定位(2026-10-04 用户拍板)

任务清单入口=**左侧菜单栏一级菜单**(与会话/通讯录同级,常驻可见),不埋在个人设置页内——高频独立面,桌面端左栏、移动端一级 Tab。

## 1. 个人 todolist 设计要点

- **每个人有自己的任务清单**：自己添加、勾完成、设提醒；
- **他人分配**：别人（同群/同组织，按权限模型）可以把任务分配给你——出现在你的清单，标来源+可跳转看分配上下文；
- **外部任务**：外部工具（GitHub/Jira/飞书…）的任务经 provider 拉进来展示，**点击跳转外部看详情**（detailUrl），完成状态可回写（按 provider 能力）。

## 2. Provider 分级（接入深度）

| 级 | 能力 | 实现 |
|---|---|---|
| **L1 跳转** | 带 detailUrl 打开外部详情 | URL 模板即可，成本最低 |
| **L2 只读** | 拉外部任务列表/状态展示 | provider 实现 list() |
| **L3 双向** | memex 内创建/完成回写外部 | create()/complete() + webhook 或轮询同步 |

Provider SPI：`id / name / auth / capabilities(L1|L2|L3) / list / create / complete / detailUrl`——能力声明制，工具只实现自己支持的级别。

## 3. 外部工具调查矩阵（2026-10-04 核实）

| 工具 | API 面 | 可达深度 | 认证 | 结论 |
|---|---|---|---|---|
| **GitHub Issues/Projects** | REST/GraphQL 全 | L3 | PAT/OAuth/App | ✅ 首批（研发任务天然源） |
| **飞书任务** | Task v2（创建/更新/查询，负责人/关注人/自定义字段——已核实 open.feishu.cn） | L3 | tenant_access_token | ✅ 首批（国产办公） |
| **钉钉待办** | 待办任务 API（创建/查询/删除，**detailUrl 直接跳转**——已核实） | L2-L3 | 企业自建应用 token | ✅ 首批（国产办公） |
| Jira | REST v3 | L3 | OAuth/API token | ✅ 二批 |
| Linear | GraphQL | L3 | OAuth/PAT | ✅ 二批 |
| Asana / Trello / ClickUp | REST | L3 | OAuth/token | ✅ 按需 |
| Notion | REST | L2-L3 | OAuth | ✅ 按需（任务=数据库行） |
| Redmine | REST | L3 | API key | ✅ 按需 |
| 企业微信待办 | 服务端 API | L2 | 企业应用 | 按需 |
| 禅道 | API 弱（版本差异大） | L1-L2 | token | ⚠️ 缓做（先只接跳转） |
| Teambition | 停摆 | — | — | ❌ 不接 |

## 4. 结论与排期建议

- **首批**：本地 todolist（L3 全功能）+ GitHub + 飞书 + 钉钉（provider 各实现到 L2-L3，L1 跳转必带）；
- **二批**：Jira/Linear；其余按用户需求点名再加；
- **不接**：Teambition（停摆）；禅道先 L1 跳转；
- 所有 provider 凭据走加密面（R24 persona 参考件），**跳转链接是基本件**（任何 provider 都必须能跳外部详情）。

## 5. 落地件（todo R27）

- R27-1 本地 todolist：自建/完成/提醒 + 他人分配（权限模型管谁能分配）
- R27-2 Provider SPI + L1 跳转框架（URL 模板/详情跳转）
- R27-3 首批 provider：GitHub、飞书、钉钉（各做到能力声明的深度）
- R27-4 二批 provider：Jira/Linear（按需启动）
