## 1. 三个文件面

| 面 | 归属 | 谁可见 | 上传者 |
|---|---|---|---|
| **群文件** | 群组 | 群成员可读，群主/管理员可管（删/置顶/配额） | 内网客户端 |
| **个人文件** | 个人 | 仅本人 | 内网客户端 |
| **文件助手**（自己↔自己） | 个人收件箱 | 仅本人 | 内网 + **外网（唯一外网落点）** |

- 文件助手 = 备忘录文本 + 文件传输（手机发自己/外网往内传）的统一收件箱；**外网来的东西进群前由用户在内网自己转发**（安全缓冲：人工过一道目）。
- 秒传（哈希去重）、配额、过期清理在元数据层做。

## 2. 存储架构：S3 兼容抽象 + RustFS 默认

```
客户端(内网/外网) ──► memex server（权限/审计/单向控制）
                        │ 签名 URL / 代理读写
                        ▼
                 存储后端（S3 兼容抽象层）
                        │
                 默认 RustFS（compose 一键起，Rust 单二进制、自托管）
                 兼容 MinIO / 云 S3（换 endpoint 即可，可选）
```

**铁律三条**：
1. **客户端永不直连对象存储**——所有读写过 memex server（权限校验、群归属、审计、外网单向全在此层），否则对象存储裸暴露=绕过全部安全口径；
2. **权限永远在元数据层判，对象层只管字节**；
3. 对象前缀划分：`groups/{gid}/`、`users/{uid}/`、外网上传 `inbox/{uid}/`。

选型理由（对比本地磁盘）：秒传/分片/断点续传 S3 协议原生（分片上传/HEAD）、大体量扩容现成、换后端改 endpoint；代价=多一个容器（compose 一行）。RustFS 自托管零依赖、不碰云——贴「不出内网」口径。

## 3. 外网单向传入（数据摆渡）

**铁律：外网会话只有「写入」权限，永远没有「读取内网数据」的权限**——否则外网客户端即泄密通道。

| 动作 | 内网客户端 | 外网客户端 |
|---|---|---|
| 浏览/下载群文件、别人文件 | ✅ | ❌ 字节不给 |
| 上传到自己空间 | ✅ | ✅（**唯一落点=文件助手**） |
| 看自己上传的记录/重下自己传的 | ✅ | ✅（仅自己的） |
| 删/管 | ✅ | 只能删自己的上传 |
| 投群 | ✅ | ❌（内网用户从文件助手转发） |

**落地三件**：
1. **两套路由两套 scope**：外网 API 独立（`uplink`），token 只发 `upload` scope；下载端点对外网 token 恒 403——单向性由**服务端权限**保证，不靠客户端自觉；
2. **物理面分离**：上传网关单独暴露（隧道出网，Cloudflare 模式），内网管理面/消息面不出网；外网客户端=「外网模式」（手机/网页），功能刻意做少（登录→传文件→看自己记录）；
3. **审计与防护**：外网上传全留痕（谁/何时/什么/落点）、杀毒扫描钩子、类型/大小白名单、账号+二次验证登录。

**安全默认**（用户硬要求）：外网入口**默认关闭、配置显式开启、开启时明示暴露范围**。

## 4. 数据模型（元数据层）

- 文件表：id、归属（gid/uid）、上传者、文件名、大小、哈希（秒传键）、对象键、来源（内网/外网）、时间、状态（正常/隔离/过期）；
- 上传记录（外网）：独立流水（审计用）；
- 配额：群/人两级。

## 5. API 面（概要）

- 内网：`/files/upload`（签名/代理）、`/files/download`、`/files/list`（按归属）、群文件管理（删/置顶/配额）；
- 外网 uplink：`/uplink/upload`、`/uplink/mine`（自己的记录）、`/uplink/delete/{id}`（自己的）——**无任何下载内网数据的端点**。
