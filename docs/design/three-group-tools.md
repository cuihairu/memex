# Three Group Tools: Polls / Sign-up Chains / Group Tasks (Phase Two Close-out Increment)

> Status: the server-surface minimal closed loop + client Dialog + poll-deadline auto-close + the three residual small items (anonymous/multi-choice, sign-up chain format validation, result card back to the group) have all landed (2026-10-08, ctest 57/57). Deadline auto-close implementation difference: **lazy evaluation** — vote_poll at the deadline (deadline_ms>0 and now>=deadline_ms) is treated as already closed and rejected with 409 (the message「投票已到截止时间」belongs to the same family as the post-close「投票已截止」), with the same judgment as a fallback at the store layer; the list returns `status` (closed|open) computed live against the deadline, and **the closed DB value is not forcibly written back** (preserving the "manual close" trace semantics — after the deadline, the initiator's manual close can still back-fill with 200, and a duplicate close gets 409, behavior equivalent to write-back and idempotent); the client's poll-initiation area has a「设截止」checkbox + QDateTimeEdit (unchecked = no deadline), list rows render grayed-out per status when past deadline, and voting has no local deadline gate (the server rejects authoritatively, and the status line states the 409).
>
> The three residual small items' implementation stance (landed 2026-10-08): **① anonymous/multi-choice** — group_polls gains the anonymous/multi columns (ALTER migration for old DBs, default 0). Multi-choice = choice stores a bit set (bit i = selected option i+1; one person still gets one row by PK counting one vote; changing the vote = the whole set is overwritten), with counts expanded bitwise; anonymous = **display-level anonymity** (votes returns an empty array, counts as usual, the row renders「匿名投票不展示投票人」; the account is still kept in the DB for change-vote upsert and audit — not cryptographic anonymity). **② Sign-up chain format validation** — when format_hint contains「+」, entry-segment-count structural validation applies (the server's 400 message states it plainly + the client rejects locally under the same stance; non-empty segments are counted, and a hint without「+」is not validated = free text, backward compatible; permission/deadline 403·409 take priority over format validation);「duplicate participation」= one-entry-per-person upsert semantics is preserved, and「append after close」409 as before. **③ Result card back to the group** — after a poll/chain is **explicitly closed**, a result card is generated and sent back as an ordinary TEXT group message (FileServer GroupTextFn callback + webhook deliver_group_text = offline queueing + archive with to=group identifier + online fan-out, the same path as a hand-sent message; the group session bubble shows the details when opened; from=the operator); the card and the list page render under the same stance (counts expanded bitwise / anonymous reports only the participant count / entries in full); a lazy deadline expiry does not send a card (no explicit action hook, avoiding duplicates), but when a manual close after the deadline back-fills, the card is sent along with it.
> Cross-references: R24 group announcements (group-domain notification surface), R25 group tools framework (external tool allowlist — these three are **native** group interactions and do not go through the R25 proxy-call skeleton), R27-1 personal task list (personal-domain tasks; group tasks are group-domain collaboration items), and the bot platform (poll/chain result cards back to the group is accepted — sent back as ordinary TEXT group messages, not a bot-surface matter, the seventh entry on 2026-10-08; bot broadcast enhancement remains for later).

## 0. Scope decision

The phase-two item "group tools (bots / polls / sign-up chains / group tasks)": bots are already covered by the bot platform (line158), and group announcements by R24-1; this draft details the remaining three **native** tools. The minimal phase-one form:

- **Polls**: named/anonymous × single/multi-choice all supported (intranet stance — named is consistent with the trace-leaving principle; anonymous = **display-level anonymity**: votes are not returned, and the account is kept in the DB for vote changes and audit; closed with the seventh entry on 2026-10-08, closing what was originally "anonymous votes deferred"); initiate (topic + 2–10 options + optional deadline) → members vote (changing the vote = overwrite) → the tally is visible in real time; the initiator or the group owner/admins can close the poll early.
- **Sign-up chains**: initiate (topic + optional format hint) → members append one after another (one entry per person; duplicate submission = update your own entry); order = submission-time order.
- **Group tasks**: group collaboration tasks (title + optional assignee = claim-based + optional deadline); claim (when unclaimed); completion = the assignee, the creator, or the group owner/admins; done is a terminal state that leaves a trace and is neither reopened nor deleted (aligned with the approval-ledger stance).

Deferred-items reconciliation (2026-10-10): five items are collected — anonymous voting, multi-choice, deadline auto-close, sign-up chain format validation, result cards back to the group (all landed with the sixth/seventh entries on 2026-10-08; implementation stance in the status lines at the head of this document); the sixth item, **the group-task deadline surface and at-deadline reminders**, was closed the same day — the client's group-task page gains a「设截止」checkbox + QDateTimeEdit (same row style as the poll deadline; unchecked = no deadline; the server-side due_ms field was already in place, and FilesClient adds the optional parameter), with list rows rendering「｜截止 MM-dd HH:mm」; the at-deadline reminder = 30s polling of check_due_tasks (todo and past deadline and not yet reminded → notification center IMPORTANT; **the reminder target = the assignee, or the creator when unclaimed** [whoever assigned it watches it; other members are not disturbed]; QSet deduplication within a session = the open-window-period stance, recounted when the window reopens — same as the R27-1 initial version; making it a resident background task when the window is closed was not done, honestly noted). As of this draft there are no uncollected residuals.

## 1. Permission decisions and trace leaving

- All action permission decisions follow the existing az rules, **nothing self-invented**: group membership (`file:read` inherited for the group — authorized the moment you join, lost the moment you leave) is enough to read and participate — the same decision shape as R25 list/call (`tool_call_allowed` isomorphic: `authorize({account,"file:read","group:N"})`).
- Identity constraints are decided in server-side logic (no new az verbs): closing a poll/chain = the initiator personally or the group owner/admins (owner||admin, same stance as the R24-1 announcement permission decision); task completion = the assignee, the creator, or the group owner/admins.
- Ghost stance: an invalid gid / non-member uniformly gets 403 (existence not leaked); a ghost poll/chain/task id gets 404 (a resource number within the membership domain).
- Trace leaving: the three-table ledger is itself the trace (who initiated/voted/appended/claimed/closed/completed + the moment); vote-change overwrites and chain updates keep no revision history (lightweight interactive tools; approval-grade retention requirements do not apply).

## 2. Storage (three store domains, six tables)

- `group_polls` (id/topic/options_json[string array]/deadline_ms[0=none, >0=auto-close at deadline — lazy evaluation without writing closed back, see the implementation-difference status line]/closed/created_by/created_ms) + `group_poll_votes` (poll_id+account PK, choice, ts_ms; upsert = change vote).
- `group_chains` (id/title/format_hint/closed/created_by/created_ms) + `group_chain_entries` (chain_id+account PK, content, ts_ms; upsert = edit your own entry).
- `group_tasks` (id/title/assignee[empty=awaiting claim]/due_ms/status todo|done/created_by/created_ms/done_by/done_ms).

## 3. Routes (twelve FileServer routes, all with group-member permission decisions)

POST /files/group-polls (create: topic non-empty, options≥2 and ≤10), GET /files/group-polls?gid= (list: each item carries options/per-person votes/named ledger/tally statistics), POST /files/group-polls/vote (not closed, out-of-range option 400, vote change overwrites), POST /files/group-polls/close (initiator or group owner/admins; already closed 409);
POST /files/group-chains, GET /files/group-chains?gid=, POST /files/group-chains/join (not closed, content non-empty; one entry per person upsert), POST /files/group-chains/close (same stance as close);
POST /files/group-tasks (a non-empty assignee must be a group member, ghost rejected 404), GET /files/group-tasks?gid=, POST /files/group-tasks/claim (todo and unclaimed, already taken 409), POST /files/group-tasks/done (assignee/creator/group owner-admins; not todo 409).

## 4. Test stance (test_files_api extended legs)

Polls: create legs (401/non-member 403/options<2 400/create 200), list with statistics and named votes, voting (out-of-range 400/vote change overwrites to the same choice/after close 409), and three close legs (uninvolved 403/initiator 200/duplicate close 409). Chains: create/non-member 403/join/update your own entry while others' entries are untouched/join after close 409.
