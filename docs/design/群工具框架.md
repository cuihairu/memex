# 群工具框架设计：CI/CD / 打包 / 配置导出（R25 设计稿）

> 状态：设计稿（2026-10-04 用户需求）。定位：群内置的**工具能力面**——入群即得能力，操作全留痕。与机器人计划（bot）互补：群工具=第一方内置 UI 与动作，机器人=开发者经 token 接入处理消息。互引：todo R25、群组知识共享（R24 密码箱=工具凭据存储面）。

## 1. 核心模型

- **群=授权域**：管理员给群配工具（白名单动作清单），**入群即有所属工具能力、退群即失**——权限跟着群走，不建独立授权体系。
- **工具=插件式配置**：一类工具=若干动作（action）+ 若干视图（status/列表）。内置首批：CI/CD（看状态/触发构建）、打包工具（一键出产物）、配置导出。
- **动作语义**：客户端点按钮 → **服务端代理调用**外部系统（GitHub Actions/API/内部服务）→ 结果回群（消息卡片+工具面板状态）。

## 2. 留痕（铁律对齐）

每次工具动作留痕：**谁/何时/哪个工具/什么动作/参数/结果**——进群日志（与审计面同源）。「点击运行」这类触发必须能回溯到人（用户点名：点击下就可以看到谁点了运行）。

## 3. 安全口径

- **外部凭据只存服务端**（CI token/接口密钥 → 复用 R24 密码箱加密面），客户端只见按钮不见密钥；
- 工具动作白名单制（工具只暴露声明的动作，无自由参数逃逸）；参数校验在服务端；
- 破坏性动作（取消构建/删产物）可配置二次确认。

## 4. 与既有面的关系

| 面 | 管什么 | 关系 |
|---|---|---|
| 群工具（R25） | 第一方工具动作+状态视图 | 入群即授权 |
| 机器人计划（bot） | 开发者接入处理消息 | 互补，不重叠 |
| 群密码箱（R24） | 共享凭据 | 工具凭据同款加密面 |
| 三级推送 | 通知 | 构建完成/失败→工具结果卡片可走推送 |
