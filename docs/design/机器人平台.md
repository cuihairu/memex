# 机器人平台（bot）设计稿

对标 Telegram Bot 的开发体验：管理台（CLI）创建机器人、发 token、开发者用
「几行代码」（curl／shell／任意 HTTP 客户端）跑通收发。内网场景：消息接收
先做**长轮询式拉取**（其实为非阻塞 drain，见 §3 注明），webhook 回调开发者
自建服务留后续。

## 0. 范围

**本笔落地**：

- bot 账号体系：CLI 创建（`bot add`）、独立 token、加群／被私聊；
- 消息收发双模式之**拉**：`POST /bot/send` 发送 + `GET /bot/updates` 拉取
  ＋ `POST /bot/ack` 确认；
- 开发体验：curl 示例＋`examples/echo_bot.sh`（收到什么打印什么）；
- 权限边界：disabled 403、群发送须 bot 是成员；
- 留痕口径：bot 消息与普通 TEXT/NOTICE 同链路**全量进留痕归档**。

**留后续（如实注明，不造假绿）**：

- webhook 回调开发者服务（bot 收到消息后回调开发者 URL——内网开发者服务
  常驻形态，需要回调重试／签名等配套）；
- 真挂起长轮询（timeout 参数阻塞等待新消息——会卡共享 io_context，需
  独立投递线程，另行排期；现版 updates 即拉即回，空则回空数组）；
- 细粒度权限（bot 可用范围按部门／按群白名单收紧）；
- bot 上报主动事件（成员变动等回调）。

## 1. 身份模型：bot 是伪账号 `bot:<name>`

不做 users 表迁移：`group_members` 与 `offline_messages` 两表**均无外键**，
伪账号 `bot:<name>` 直接可用——

- bot 加群 = 直插 `group_members(group_id, 'bot:<name>', joined_ms)`；
- TEXT 扇出（session.cpp）对群成员逐人 `queue_offline`，成员里有
  `bot:<name>` 就自动入 bot 的离线队列——**零改动**；
- 单聊 `to=bot:<name>` 直接入队（TEXT 单聊路径不校验账号存在）——零改动；
- bot 名与真实账号同空间不可混淆：前缀 `bot:` 保留，CLI 创建时校验
  name 非空且不含 `:`。

bots 表只管**凭据与开关**：

```sql
CREATE TABLE IF NOT EXISTS bots (
  name TEXT PRIMARY KEY,        -- 不含 "bot:" 前缀
  token_hash TEXT NOT NULL UNIQUE,
  created_by TEXT NOT NULL,
  created_ms INTEGER NOT NULL,
  disabled INTEGER NOT NULL DEFAULT 0);
```

token 明文仅 `bot add` 时输出一次，库存 sha256 摘要（同 webhook 口径）。

## 2. 发送：POST /bot/send

Bearer token 鉴权（webhook 端口共用，T4.10 投递面）：

```
POST /bot/send
Authorization: Bearer <token>
{"target": "group:5" | "alice", "text": "构建完成 ✓"}
```

| 情形 | 状态码 |
| --- | --- |
| token 缺失／无效 | 401 |
| bot 已禁用 | 403 |
| target 缺失／text 为空 | 400 |
| 群不存在／账号不存在 | 404 |
| 群发送但 bot 非成员 | 403 |

成功即复用 `deliver_notice` 投递链（NOTICE 信封）：**deliver_notice 加
sender 参数**（缺省 `kNoticeSender` 通知行为不变；bot 传 `"bot:<name>"`）
——msg_id 派生、离线入队、**归档 from=bot:<name>**、在线扇出、常用联系
人全链不变。bot 消息 title=bot 显示名（`bot:<name>`）、content=text，
归档正文与客户端展示同源（compose_notice_text）。

## 3. 接收：GET /bot/updates ＋ POST /bot/ack

离线队列即 bot 收件箱（TEXT 扇出自动入队，见 §1）：

```
GET /bot/updates
Authorization: Bearer <token>
→ {"ok":true,"updates":[{"msg_id":"…","from":"alice","to":"bot:echo",
   "text":"你好","ts_ms":1697…}]}

POST /bot/ack  {"msg_id":"…"}   → {"ok":true}
```

updates 把 `pending_offline("bot:<name>")` 的 protobuf blob 逐条解码成
JSON（只解 TEXT；NOTICE 等其余类型原样跳过不解码——bot 收发面只承诺
文本）。**非阻塞 drain**：即拉即回、空则空数组。真挂起长轮询（timeout
阻塞等新消息）会卡死与 CollabServer 共享的单线程 io_context，留后续
（§0）；客户端轮询即可（echo bot 1s 间隔）。

ack 后消息从队列清除（至少一次投递＋ACK 清，同 TEXT 离线补投语义）。

## 4. CLI（管理台）

```
memex_server bot add <name> --by <账号>        # token 明文仅此一次显示
memex_server bot list
memex_server bot remove <name>
memex_server bot disable|enable <name>
memex_server bot join <name> <群号>            # 加群后可收群消息／可群发
memex_server bot leave <name> <群号>
```

## 5. 开发体验：几行代码跑通

```bash
# 创建（管理台）
memex_server bot add echo --by admin1
#   token：bot_xxx…（仅此一次）

# 收发（开发者）
TOKEN=bot_xxx…
curl -s -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"target":"alice","text":"hello"}' http://<服务器>:<port>/bot/send
curl -s -H "Authorization: Bearer $TOKEN" http://<服务器>:<port>/bot/updates
curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"msg_id":"…"}' http://<服务器>:<port>/bot/ack
```

`examples/echo_bot.sh`：收到什么打印什么（updates 轮询＋ack＋原样回发，
jq 可缺省退化 grep 解析）。

## 6. 测试口径

仿 test_webhook.cpp：真 store＋真 WebhookServer（port=0）＋ HTTP 往返。
腿：错 token 401／disabled 403／幽灵群 404／非成员群发 403／加群后 200

出到达 bot 队列（登录用户发群消息，bot updates 拉到）／单聊 to=bot:…
入队／updates 不带 Authorization 401。
