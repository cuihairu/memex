# 机器人平台（bot）设计稿

对标 Telegram Bot 的开发体验：管理台（CLI）创建机器人、发 token、开发者用
「几行代码」（curl／shell／任意 HTTP 客户端）跑通收发。内网场景：消息接收
做**长轮询式拉取**（`GET /bot/updates?timeout_ms=N` 真挂起，见 §3），
webhook 回调开发者自建服务留后续。

## 0. 范围

**本笔落地**：

- bot 账号体系：CLI 创建（`bot add`）、独立 token、加群／被私聊；
- 消息收发双模式之**拉**：`POST /bot/send` 发送 + `GET /bot/updates` 拉取
  ＋ `POST /bot/ack` 确认；
- 开发体验：curl 示例＋`examples/echo_bot.sh`（收到什么打印什么）；
- 权限边界：disabled 403、群发送须 bot 是成员；
- 留痕口径：bot 消息与普通 TEXT/NOTICE 同链路**全量进留痕归档**。

**2026-10-11 追加**：真挂起长轮询收口——`GET /bot/updates?timeout_ms=N`
空队挂起至新消息入队或到期（§3）。零新增线程：挂起定时器挂在共享
io_context 上，唤醒源＝`ServerStore::queue_offline` 真落新行后的入队钩子
（与全部入队点同线程，无锁）；上限 30s 防连接永久挂起。

**2026-10-11 追加（同日第二批）**：细粒度权限白名单收口（§2.1）——群
白名单（名单非空 ⇒ bot 群成员资格 ⊆ 名单，allow/deny 变动连带退名单外
群；join 名单外群 store 层拒）＋部门白名单（单聊目标部门须落白名单子
树，未分配从严）；名单空＝不设限（存量 bot 行为零变化）；入站不裁——
白名单管 bot 能主动动谁，不管谁能找 bot。

**留后续（如实注明，不造假绿）**：

- webhook 回调开发者服务（bot 收到消息后回调开发者 URL——内网开发者服务
  常驻形态，需要回调重试／签名等配套）；
- bot 上报主动事件（成员变动等回调）。

## 1. 身份模型：bot 是伪账号 `bot:<name>`

不做 users 表迁移：`group_members` 与 `offline_messages` 两表**均无外键**，
伪账号 `bot:<name>` 直接可用——

- bot 加群 = 直插 `group_members(group_id, 'bot:<name>', joined_ms)`；
- TEXT 扇出（session.cpp）对群成员逐人 `queue_offline`，成员里有
  `bot:<name>` 就自动入 bot 的离线队列——**零改动**；
- 单聊 `to=bot:<name>` 直接入队（TEXT 单聊路径不校验账号存在）——零改动；
- bot 名与真实账号同空间不可混淆：前缀 `bot:` 保留，CLI 创建时校验
  name 非空且不含 `:`。

bots 表只管**凭据与开关**：

```sql
CREATE TABLE IF NOT EXISTS bots (
  name TEXT PRIMARY KEY,        -- 不含 "bot:" 前缀
  token_hash TEXT NOT NULL UNIQUE,
  created_by TEXT NOT NULL,
  created_ms INTEGER NOT NULL,
  disabled INTEGER NOT NULL DEFAULT 0);
```

token 明文仅 `bot add` 时输出一次，库存 sha256 摘要（同 webhook 口径）。

可用范围名单（细粒度权限，§2.1）另开两表——同样无外键（同
group_members 口径），`bot remove` 连带清：

```sql
CREATE TABLE IF NOT EXISTS bot_group_allow (
  name TEXT NOT NULL,
  group_id INTEGER NOT NULL,
  created_ms INTEGER NOT NULL,
  UNIQUE(name, group_id));
CREATE TABLE IF NOT EXISTS bot_dept_allow (
  name TEXT NOT NULL,
  department_path TEXT NOT NULL,
  created_ms INTEGER NOT NULL,
  UNIQUE(name, department_path));
```

## 2. 发送：POST /bot/send

Bearer token 鉴权（webhook 端口共用，T4.10 投递面）：

```
POST /bot/send
Authorization: Bearer <token>
{"target": "group:5" | "alice", "text": "构建完成 ✓"}
```

| 情形 | 状态码 |
| --- | --- |
| token 缺失／无效 | 401 |
| bot 已禁用 | 403 |
| target 缺失／text 为空 | 400 |
| 群不存在／账号不存在 | 404 |
| 群不在 bot 可用白名单（名单非空时） | 403 |
| 账号不在 bot 可用部门白名单（名单非空时） | 403 |
| 群发送但 bot 非成员 | 403 |

白名单两道 403 的位置：群目标在群存在性 404 之后、成员资格 403 之
前（组织级配置先于群级成员关系）；账号目标在 `deliver_notice` 之前（名
单不辖幽灵账号——账号存在性 404 由 `deliver_notice` 保既有语义）。

成功即复用 `deliver_notice` 投递链（NOTICE 信封）：**deliver_notice 加
sender 参数**（缺省 `kNoticeSender` 通知行为不变；bot 传 `"bot:<name>"`）
——msg_id 派生、离线入队、**归档 from=bot:<name>**、在线扇出、常用联系
人全链不变。bot 消息 title=bot 显示名（`bot:<name>`）、content=text，
归档正文与客户端展示同源（compose_notice_text）。

### 2.1 可用范围白名单（细粒度权限）

口径：**名单非空才收紧，空＝不设限**——存量 bot 不配名单行为零变化
（`bot_group_allowed`／`bot_account_allowed` 名单空恒放行）。名单不存
删除语义（deny 只是移除条目），幽灵账号不属名单管辖（放行交 404）。

- **群白名单**（`bot_group_allow`）：不变式＝名单非空时 bot 群成员资格
  ⊆ 名单。allow/deny 后统一扫尾：不在名单的群连带退群
  （`bot_prune_group_membership`，EXISTS 守卫＝名单非空才扫，空名单不
  动成员资格）；deny 另显式退出该群（名单复空＝不设限不扫尾，不显式
  退则 bot 滞留群内还能收发）；`bot_join_group` 对名单外群 store 层拒
  （CLI `bot join` 同拒）。于是「管理员事后把群移出名单」即时生效
  ——bot 当场退群、该群消息不再入 bot 队列（扇出只达在册成员）。
- **部门白名单**（`bot_dept_allow`）：单聊目标账号的 `department_path`
  须等于某白名单路径或为其子树——「/」段边界前缀匹配（防「研发」误
  吞「研发部」，与 PolicyRow 逐级上溯同族口径）；未分配部门从严（跨
  部门文件同款先例）；路径须已存在（allow 不隐式建部门）。
- **入站不裁（如实注明）**：白名单管 bot 能**主动动谁**（send/join），
  不管**谁能找 bot**——入站单聊直达与 TEXT 扇出零改动是 bot 面立身
  之本（群内智能助手、echo 演示均依赖），名单不挡入站。

CLI：`memex_server bot allow|deny <name> --group <群号> | --dept <部门全路径>`
维护名单（CLI `bot list` 尾列白名单摘要：`群{…} 部门{…}`，空显示 `-`）。

## 3. 接收：GET /bot/updates ＋ POST /bot/ack

离线队列即 bot 收件箱（TEXT 扇出自动入队，见 §1）：

```
GET /bot/updates[?timeout_ms=N]
Authorization: Bearer <token>
→ {"ok":true,"updates":[{"msg_id":"…","from":"alice","to":"bot:echo",
   "text":"你好","ts_ms":1697…}]}

POST /bot/ack  {"msg_id":"…"}   → {"ok":true}
```

updates 把 `pending_offline("bot:<name>")` 的 protobuf blob 逐条解码成
JSON（只解 TEXT；NOTICE 等其余类型原样跳过不解码——bot 收发面只承诺
文本）。**长轮询**：`timeout_ms=N`（毫秒，0 缺省＝即拉即回原口径）且队
列空时挂起请求，至该 bot 有新消息入队（提前回，必非空）或到期（回空数
组）；上限 30000ms 截断，非数字 400。实现为零新增线程——挂起定时器挂
与 CollabServer 共享的单线程 io_context，唤醒＝`ServerStore::queue_offline`
真落新行（`sqlite3_changes`>0，撞键 IGNORE 不唤醒）触发的入队钩子（与
全部入队点同线程，登记/取消无竞态）；挂起期连接引用由挂起表兜底，客户端
断开则到期/唤醒时写回失败自然收场。带参非空队／不带参均即拉即回。

ack 后消息从队列清除（至少一次投递＋ACK 清，同 TEXT 离线补投语义）。

## 4. CLI（管理台）

```
memex_server bot add <name> --by <账号>        # token 明文仅此一次显示
memex_server bot list                          # 尾列白名单摘要
memex_server bot remove <name>
memex_server bot disable|enable <name>
memex_server bot join <name> <群号>            # 加群后可收群消息／可群发
memex_server bot leave <name> <群号>
memex_server bot allow|deny <name> --group <群号>    # 群白名单（§2.1）
memex_server bot allow|deny <name> --dept <部门全路径>  # 部门白名单（§2.1）
```

## 5. 开发体验：几行代码跑通

```bash
# 创建（管理台）
memex_server bot add echo --by admin1
#   token：bot_xxx…（仅此一次）

# 收发（开发者）
TOKEN=bot_xxx…
curl -s -H "Authorization: Bearer $TOKEN" \
     -H 'Content-Type: application/json' \
     -d '{"target":"alice","text":"hello"}' http://<服务器>:<port>/bot/send
curl -s -H "Authorization: Bearer $TOKEN" http://<服务器>:<port>/bot/updates
curl -s -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
     -d '{"msg_id":"…"}' http://<服务器>:<port>/bot/ack
```

`examples/echo_bot.sh`：收到什么打印什么（updates 轮询＋ack＋原样回发，
jq 可缺省退化 grep 解析）。
