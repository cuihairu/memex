## 一、建群询问主题/目的

### 1.1 弹窗与字段

建群时弹出一屏（现建群弹窗扩为两步同屏）：

| 字段 | 形态 | 必填性 | 落点 |
|---|---|---|---|
| **主题** | 单行，一句话 | 必填（客户端弹窗层强制，见 1.3） | 群资料 `topic` |
| **目的** | 多行说明 | 选填 | 群资料 `purpose` |

- 值落群资料，在**群头像/群名下方**可见（群资料页＋聊天页群头部同位）；
- **可后期编辑**：编辑权沿群公告先例（群主/管理员，`group_memo` 判权同
  源），编辑入口在群资料页；
- 三端同源：桌面/手机/admin 读同一 `group_info` 现查字段，不出现第二份
  群资料。

### 1.2 落库

`groups` 表加两列（ALTER＋默认值循 provider/ext_key 列迁移写法，不重建
表）：

```sql
ALTER TABLE groups ADD COLUMN topic   TEXT NOT NULL DEFAULT '';
ALTER TABLE groups ADD COLUMN purpose TEXT NOT NULL DEFAULT '';
```

存量群两列落空串（＝「主题未填」态，资料页如实标注）。

### 1.3 协议与兼容

- 建群帧与群资料编辑帧加**可选**字段 topic/purpose；老客户端不填→服务
  端落默认空串，行为不变（协议兼容口径）；
- 「主题必填」在**客户端弹窗层**强制（空主题提交按钮置灰），服务端不强
  拒空主题——否则老客户端建群全部失败；
- **待拍板①**：建群能否跳过主题。给跳过按钮＝主题实际选填（跳过后落空
  串、资料页标「主题未填」）；不给＝真必填。两案都在本设计的实现面内，
  拍板即定 UI 与校验分支。

### 1.4 验收（可测）

- 建群弹窗：空主题不可提交（或跳过按拍板①分支）；目的可空；
- 落库后 `group_info` 回带 topic/purpose；资料页头像/群名下方展示；
- 群主/管理员可编辑、普通成员编辑被拒（403，群公告同款判权）；
- 老协议帧（不带新字段）建群成功且群资料两列为空串。

## 二、群记录导出

### 2.1 导出内容（固定三段）

| 段 | 内容 | 数据源（现成） |
|---|---|---|
| **参与人** | 成员名单＋角色＋加入时间 | `group_members.joined_ms`（现成）；**离开时间现库不留痕**（退群即摘行）——如实注记「离开时间不含」，若要带须另立成员变动台账，不并入本期 |
| **时间范围** | 建群时间＋所选区间 | `groups.created_ms`（现成）＋导出参数 from/to |
| **聊天记录** | 所选区间内消息，含发送人与时间戳 | `search_messages`（见 2.2），区间参数 since_ms/until_ms |

### 2.2 复用现有能力（不新建导出引擎）

- **查询层＝`search_messages`**（store.hpp `MessageSearch`）：`peer=
  "group:N"`＋`account=导出者`＋`since_ms/until_ms=所选区间`——与会话
  历史/CLI/管理台检索**同一查询层**（需求批⑧口径），**所见即历史面所
  见**，无越权新数据面；导出者退群后 peer 联不上＝空结果，天然权限边界。
- **导出面先例两件**：①admin 归档检索导出（`messages --as`，auditor 凭
  据＋落 `audit_reads`，平台-6 红线口径）；②`/files/group-export`
  （R25 快照导出：`memo:config`＝群主/管理员判权＋导出即留痕）——本特
  性取②的**群面判权与留痕思想**＋①的**审计表**（audit_reads），不复制
  auditor 门槛（见 2.5 平台-6 边界）。
- **格式**：Markdown 为仓内默认产出（对话体：`[时间] 发送人: 内容`，
  撤回行带标记）；**docx 不内置转换器**——需要时经外部现成工具后转
  （pandoc 一类），仓内只保证 Markdown 质量口径（**待拍板④** 默认格式）。
- **条数上限与分页（默认值，可调）**：单页 1000 条（`MessageSearch.limit`
  现量级）；单次导出上限 **10000 条**，超出自动分页——响应带
  `has_more`＋`next_since` 游标，客户端逐页拼接；触顶截断时文档尾部
  `truncated` 标注（截断时刻与续传入口写明，不静默截尾）。

### 2.3 两档：普通文档与 AI 总结档

- **无 AI＝普通文档**：纯记录三段，无总结；
- **有 AI＝文档头部加「总结」章节**：依赖 R11 内网模型与模型网关
  （docs/design/模型网关.md、群内智能助手.md——**现只有设计稿，三期**）；
- **降级口径（写死）**：模型未接线/网关不可达时**必须自动降级为普通文
  档，并在导出结果里注明「AI 未启用」**——不许假装有总结、不许空总结
  章节占位；
- **铁律**：归档数据只送本地模型（R11 口径），导出总结链路同样不出内网
  ——与「数据默认不出门」硬约束同源。

### 2.4 留痕边界

- 导出是**副本**，**不动归档**（R3 铁律：不提供任何可消除已归档内容的
  功能；导出路径对归档只读）；
- **导出行为记一条审计**（谁、何时、导出哪个群哪个区间、条数）：落现成
  `audit_reads` 表（action=`group_record_export`，filters=gid/from/to/
  条数）——与检索导出面同表同思想，不新表（**待拍板③**，建议记）。

### 2.5 权限与平台-6 边界

- 谁能导出＝**待拍板②**（三选一：A 群主与管理员——循 `/files/group-
  export` 的 `memo:config` 先例；B 全员＝本群成员；C 仅本人消息段＝
  同 A/B 门＋导出内容过滤 sender==本人）；
- 无论哪案：导出面**只对本群角色开放**，org-admin 无本群角色不可见——
  不触碰平台-6 红线（消息内容不向 org-admin 开放）；跨群内容永不出现在
  导出里。

### 2.6 大群/长区间验收（可测）

- 分页：区间 1 万条级导出逐页拼接完整，页序无重无漏（游标续传）；
- 进度：客户端按「页 x/y」展示进度，可中断；
- 失败重试：单页失败重试 3 次（幂等由 since/until 游标保证，重试不重复
  入文档）；
- 截断：触单次上限→尾部 `truncated` 标注＋续传入口；
- 审计：每次导出 `audit_reads` 恰一行，跨两次导出两行；
- 不动归档：导出前后归档行数与内容逐位一致（R3 断言）；
- 降级：模型网关不可达→普通文档＋「AI 未启用」注明（无总结章节）。

## 三、落库与接口汇总

| 变更 | 口径 |
|---|---|
| `groups` 加 `topic`/`purpose`（TEXT DEFAULT ''） | ALTER＋默认值，存量落空串＝「主题未填」态 |
| 建群/群资料帧加可选 topic/purpose | 老客户端不填→空串，行为不变 |
| 导出路由（files 面新路由，`peer=group:N` 查询） | 判权按拍板②；落 `audit_reads`；分页游标；AI 档降级注明 |
| `audit_reads` 复用 | action=`group_record_export`，不新表 |
