## 1. P0：发布阻断级安全与消息可靠性

### P0-1 协作态 TCP 传输没有可见的 TLS 保护

-   [ ] **现状核实与修复：协作态密码及消息传输加密。**
-   代码证据：`client/engine/collab/collab_engine.cpp` 创建
    `QTcpSocket`；`send_login_frame()` 将 `password_` 原样写入
    `LOGIN.password`；`server/src/server.cpp` 以普通 Asio TCP acceptor
    接入，`server/src/session.cpp` 未见 TLS/SSL
    处理。应在本地全仓再确认是否存在外部强制加密的部署层，不能默认存在。
-   风险：若客户端到服务端链路经过可监听的
    LAN、跨网段或不可信隧道，账号口令和聊天内容可被旁路读取/篡改；单纯在数据库使用
    PBKDF2 不保护网络传输。
-   修复要求：制定唯一、可部署的端到端传输保护方案（优先客户端---服务端
    TLS；或有明确边界的受支持 TLS 封装）。验证服务器证书/受信
    CA；证书错误必须失败关闭；不得静默降级为明文。若某种部署模式不支持加密，必须默认禁止或给出明确阻断提示，不能只写文档提醒。
-   同步检查：`/files/*`、`/uplink/*`、admin 登录及 Bearer token 的 HTTP
    入口是否只能经 HTTPS
    访问；Docker/反代/隧道配置是否会意外暴露明文端口。
-   验收：抓包确认 LOGIN
    口令、消息正文、会话令牌均不以明文出现；错误证书、过期证书、主机名不匹配、断线重连、证书轮换均有自动化测试；默认部署说明和端口暴露策略一致。

### P0-3 服务端归档与离线队列的受理语义必须一致

-   [ ] **检查归档、离线队列、在线投递和发送方 ACK

-   代码证据：`server/src/session.cpp` 消息处理路径先调用

-   修复要求：归档成功但离线队列写入失败时，不能让系统静默丢失离线投递。定义并实现可恢复的事务边界（例如同一数据库事务写归档和投递队列，或用可重建投递台账）；ACK

-   验收：分别注入归档写失败、队列写失败、投递过程中断、服务端重启、重复

### P0-4 文件接收不能在新文件完成前删除已有文件

-   [ ] **修复直连文件传输的覆盖与失败数据丢失风险。**
-   代码证据：`client/engine/direct/file_transfer.cpp`
    收件时若目标文件存在且哈希不同，会先
    `QFile::remove(in.final_path)`（约 344--366

-   修复要求：完整接收、校验 SHA-256

    part 文件，清理规则必须有明确边界。
-   验收：同名不同内容、传输中断、哈希不匹配、磁盘满、目标被占用、rename
    失败、重复传输等测试均证明原文件不会被提前破坏。

## 2. P1：高风险安全边界与状态一致性

### P1-1 直连 TOFU 首次信任不能静默完成

-   [ ] 审查首次见到设备身份密钥时的信任流程，并补齐首次信任/换钥安全
    UX。
-   代码证据：`client/engine/direct/secure_channel.cpp` 的
    `verify_pin()` 在无既有 pin 时直接写入对端公钥（约 193--204
    行）；握手路径随后按 pin 比对（约 495--516 行）。
-   风险：TOFU 可阻止后续密钥变化，但首次连接时无法单靠 TOFU
    识别主动中间人；UDP 发现内容本身不应被当作认证。
-   修复要求：首次见到身份时提供清晰、可审计的信任确认（显示设备
    ID/指纹/来源），或使用另一条可信认证通道；换钥须明确告警并走受控重置，不允许自动覆盖
    pin。不得把"发现了设备"当作"身份可信"。
-   验收：伪造发现广播、同 ID
    不同密钥、首次连接竞速、重装/数据库丢失、合法换钥、pin
    写盘失败等用例均覆盖；任何失败路径不得降级成明文。

### P1-3 协作协议的授权必须逐帧闭环

-   [ ] 建立协议消息的授权矩阵，并逐条核对服务端处理器。
-   范围：`TEXT`、`RECALL`、`ACK`、`READ`、`READ_NOTICE`、`RECEIPT_QUERY`、`MESSAGE_QUERY`、群命令/群消息、`FILE_AUTHZ`、`CROSS_LOG`、`PROFILE_CMD`、`FAV_CMD`、通知、远程协助、群记录导出、群服务器会话和管理后台敏感操作。
-   核对项：必须登录；服务端不能信任客户端伪造的
    `from/to/group_id/role`；读回执只能针对本人有权访问的消息；群成员资格必须在服务端验证；撤回者必须有权撤回目标消息；token
    scope 与资源 ID 必须匹配；拒绝结果要明确且留下必要审计。
-   修复要求：复用 `AuthorizationService` 的 default-deny
    规则，不在客户端做最终授权；对每个敏感操作都要有"授权检查 +
    明确拒绝 + 回归测试"。
-   验收：为每个操作至少添加合法主体、未登录主体、其他用户、非群成员、伪造资源
    ID、已停用账号/设备、过期/错误 scope token

-   每个迁移必须可重复运行或明确禁止重复运行；迁移失败不能留下"半升级"状态；不要用仅覆盖全新空库的测试证明升级安全。
-   验收：保留至少一个旧 schema
    fixture；升级前后行数、唯一约束、索引、归档内容与审计链校验一致。

### P2-2 自定义 HTTP 文件面协议解析器专项

-   [ ] 审查 `server/src/files_server.cpp`
    的请求行、header、Content-Length、重复 header、路径解码、body
    cap、keep-alive、超时和连接关闭语义。
-   必测：极长请求行/header、重复或溢出的 Content-Length、非法数字、body
    截断、超限 body、编码路径、慢速上传、连接提前关闭、无 Content-Length
    的 GET/DELETE/HEAD。
-   修复要求：所有输入都有显式上限与超时；解析失败必须中止请求，不得继续复用污染的解析状态；不要在反代环境形成请求边界歧义。
-   验收：fuzz/变异测试可重复；非法输入不会崩溃、无限分配、绕过鉴权或影响下一条请求。

### P2-3 口令校验与凭据生命周期

-   [ ] 盘点所有口令校验位置（消息服务、admin、文件面、LDAP
    绑定），统一凭据比较与错误处理。
-   使用恒定时间比较摘要；按性能基准评估 PBKDF2
    参数是否需要提升并设计版本化迁移，不得直接更改迭代次数导致旧凭据无法登录。
-   确认日志、异常、崩溃转储和诊断输出不包含口令、明文
    token、恢复码或完整敏感头。
-   验收：统一凭据测试、旧摘要迁移测试、日志敏感字段扫描和登录限流测试通过。

### P2-4 对象存储、文件元数据和配额一致性

-   [ ] 审查 `server/src/storage.cpp` 与 `server/src/files_server.cpp`
    的上传、秒传、删除、置顶、配额、对象键、病毒扫描和补偿流程。
-   验证对象已写但 DB 失败、DB
    已写但对象缺失、重复上传、哈希冲突、删除中断、配额并发竞态、S3/RustFS
    超时、扫描器不可用等场景。
-   保留现有"客户端不直连对象存储、授权由元数据层执行、外网 uplink
    只写不读"的边界。
-   验收：`files verify`、备份恢复演练和 S3 E2E
    均能发现孤儿/缺失对象；故障后可恢复且不突破群/个人配额。

### P2-5 直连安全密钥的存储与生命周期

-   [ ] 审查 `DeviceIdentity` 私钥种子在 SQLite
    中的存储、文件权限、备份/迁移、重装、数据库复制和销毁流程。
-   评估各平台系统密钥库/文件权限的可行性；若暂不加密，必须明确本地管理员/恶意软件可复制身份密钥的威胁模型。
-   审查 AEAD nonce
    唯一性、双向密钥隔离、计数器溢出、重复/乱序帧、握手重放、版本降级和密钥清理。
-   验收：安全协议测试覆盖
    nonce/计数器边界、畸形握手、错误签名、旧协议、重放和密钥轮换；不允许在安全初始化失败时回退明文。

### P2-6 异步任务、资源生命周期与并发

-   [ ] 全仓检查 QObject/回调捕获、线程归属、socket
    写入串行化、关闭/重连竞态、计时器取消、重复信号、悬垂引用和 shutdown
    顺序。
-   重点模块：`client/engine/collab/`、`client/engine/direct/`、`client/app/`、`server/src/session.cpp`、`server/src/server.cpp`、`admin/src/admin_app.cpp`、移动端网络会话。
-   验收：重复连接/登出/踢下线、窗口关闭、传输取消、快速切换模式、服务器重启等压力测试；启用适用的
    ASan/UBSan/TSan 或平台等价工具，报告必须注明未覆盖的平台。

### P2-7 错误处理与可观测性

-   [ ] 所有网络、磁盘、SQLite、S3、LDAP、通知、外部 provider

-   禁止静默吞掉异常/返回值；日志必须避免口令/token/聊天正文泄漏；外部输入要做长度限制和换行净化，避免日志注入。
-   增加健康检查：服务端进程存活、DB 可写、对象存储可达、队列积压、LDAP
    可达、证书到期、备份最近成功时间。健康端点不能泄露敏感配置。
-   验收：故障注入后能从日志/健康面定位故障；用户界面不会把"已发送/已归档"显示在实际未受理的情况下。

## 4. 产品范围与决策边界（不要擅自扩建）

-   [ ] **D1 音视频会议/语音通话：**
    当前协议主线没有相应媒体帧；不得为了"补齐企业微信"直接引入新媒体栈。单独提交技术选型、部署带宽、编解码、录制/归档、权限、成本和跨平台验证方案，等待产品确认。
-   [ ] **D2 独立屏幕共享/远程控制：** 远程协助中的 JPEG
    轮询抓屏不等于实时屏幕共享；`net_remote_settings`
    配置壳不等于远程控制引擎。必须分开陈述，不得在 UI/文档中夸大能力。
-   [ ] **D3 多端同时在线：**
    当前产品口径包含按设备类型互踢/单端限制；修改前先确认是否调整
    R4，不得擅自改变会话互踢规则。
-   [ ] **D4 身份源优先级：** LDAP/AD 与 OIDC
    的实施顺序、并行支持方式以用户决策为准。
-   [ ] **D5 管理授权决策：**
    账号禁用是否踢存量会话、停用设备是否踢存量会话、文件 token
    是否绑定设备、群服务器工具是否增加细粒度角色/按组授权，先核对现有待拍板项；未获决策前不得自行放宽权限。
-   [ ] **D6 HarmonyOS：** 保留后置顺序；没有真实 OHOS
    工具链时只报告逻辑层/CI 状态，不能声称 ArkTS 壳编译或真机验收通过。
